Human intent → executable evidence

아이디어가
제품이 되는
8단계

인간의 아이디어를 제품 정책으로 구체화하고, 계약·코드·테스트와 실행 증거로 연결한다. 검증 결과는 다시 인간의 다음 판단으로 돌아간다.

이 프로세스는 AI보다 오래됐다.

제품 관리자, 도메인 전문가, 개발자와 QA가 같은 변환 작업을 나누어 맡아 왔다. AI 에이전트는 이 작업을 더 빠르게 연결하지만 제품의 의미와 검증 절차를 대신 결정하지 않는다.

Intent
moves down 아이디어 제품 정책 계약 코드 테스트 사용 결과
Evidence
returns up 다음 판단 승인·수정 검증 결과 실행 증거 관찰 결과 운영 지표

Process snapshot / Search result window

정책 하나가 만들어지는 장면

검색 결과를 처음에는 10편만 보여주고, 사용자가 요청하면 같은 목록에 10편씩 추가한다는 사례를 끝까지 따라간다.

  1. Observe

    문제 포착

    검색 결과가 너무 길어 읽을 논문을 고르기 어렵다는 문제를 발견한다.

    Output 구체적인 사용자 문제
    Human

    관찰한 불편과 바라는 변화를 설명한다.

    Agent

    관찰된 문제, 추정 원인, 해결 아이디어를 분리한다.

    Skill

    product-discovery-steward가 관찰을 성급하게 구현안으로 확정하지 않도록 조사 순서를 안내한다.

    Machine

    분석 이벤트와 화면 기록이 현재 행동을 보여준다. 더 나은 경험이 무엇인지는 결정하지 않는다.

  2. Decide

    정책 결정

    “적당히 보여준다”를 “처음 10편, 이후 10편씩”으로 구체화한다.

    Output 인간이 승인한 제품 정책
    Human

    사용자에게 제공할 결과와 판단 기준을 승인한다.

    Agent

    가능한 선택지와 각 선택이 사용자 경험에 주는 영향을 정리한다.

    Skill

    mission-control이 제품 원칙, 사용 상황, 기대 결과와 충족 조건을 구분한다.

    Machine

    ID와 문서 형식을 검사한다. 숫자 10이 적절한지는 판단하지 않는다.

  3. Declare

    계약 작성

    정책을 Experience, Moment, Promise, Acceptance Check와 Aspect로 구조화한다.

    Output 검증 가능한 제품 계약
    Human

    계약 초안이 원래 의도와 사용자 경험을 보존하는지 확인한다.

    Agent

    승인된 의미를 계약 문장과 추적 가능한 ID 관계로 작성한다.

    Skill

    Contract Steward는 Promise의 종단 관계를, Aspect Steward는 여러 목록에 적용되는 공통 정책을 안내한다.

    Machine

    mc:validate-story-chain이 ID, 부모 관계, AC 존재와 Promise·Aspect의 양방향 참조를 검사한다.

  4. Scope

    구현 범위 결정

    정책을 구현할 route, component, hook, store와 기존 테스트를 찾는다.

    Output 구현 계획과 코드 연결
    Human

    제품 의미나 구조를 바꾸는 선택이 생기면 방향을 결정한다.

    Agent

    계약에서 관련 코드와 테스트로 추적하고 변경 범위를 제안한다.

    Skill

    데이터, 상태 수명, 실행 순서, AI 경계 등에 영향이 있으면 Architecture Impact Review로 보낸다.

    Machine

    코드 검색과 surface audit가 누락된 파일과 잘못된 참조를 찾는다.

  5. Build

    코드와 테스트 작성

    처음 10편을 렌더하고 요청할 때 같은 목록에 10편씩 추가한다.

    Output 코드와 재현 가능한 테스트
    Human

    중간 결과가 승인된 정책과 다르면 의미와 우선순위를 바로잡는다.

    Agent

    UI와 상태 로직을 구현하고 경계값과 실패 조건을 테스트로 만든다.

    Skill

    구현 스킬이 저장소의 상태 소유권, 코드 경계와 테스트 관례를 알려준다.

    Machine

    TypeScript와 lint가 정적 오류를 찾고 Vitest가 DOM 결과를 검사한다.

  6. Prove

    실행 증거 연결

    각 Acceptance Check를 실제로 실행할 테스트와 Evidence Ledger 행에 연결한다.

    Output 조건별 실행 증거
    Human

    증거가 제품 의도를 충분히 입증하는지 의미를 검토한다.

    Agent

    조건, 실행 명령, 테스트, 적용 범위를 한 Ledger 행으로 연결한다.

    Skill

    Contract Steward가 모든 조건에 증거를 붙이고 낡은 참조를 제거하게 한다.

    Machine

    dry-run이 명령과 필터를 검사한다. runner는 하나 이상의 테스트가 선택되는지 확인한 뒤 실행한다.

  7. Review

    통합 검증과 승인

    계약, 코드, 테스트와 증거가 함께 유지되는지 확인한다.

    Output 배포 가능한 변경
    Human

    제품 의미와 실행 증거의 충분성을 최종 검토한다.

    Agent

    실패를 계약, 구현, 증거 문제로 분류하고 해당 범위를 수정한다.

    Skill

    Mission Control이 제품 원칙부터 증거까지의 리뷰 순서를 제공한다.

    Machine

    quality:contract, 테스트, audit와 mc:status가 끊어진 참조와 실패를 차단한다.

  8. Learn

    사용 결과 반영

    배포 뒤의 관찰을 다음 제품 판단의 입력으로 돌려보낸다.

    Output 유지·수정·철회 결정
    Human

    사용 결과를 보고 정책을 유지하거나 제품 결정을 다시 연다.

    Agent

    피드백과 사용 데이터를 기존 정책과 증거에 연결한다.

    Skill

    discovery 절차가 새 관찰과 기존 결정을 구분해 같은 흐름으로 되돌린다.

    Machine

    analytics가 행동, 오류와 성능을 수집한다. 수치는 판단의 증거로 쓰인다.

Contract vocabulary

정책을 검증 가능한 단위로 나눈다

Experience
오래 유지할 제품 경험이다. 연구 결과와 논문 관계를 탐색하는 전체 경험을 다룬다.
Moment
제품 동작이 필요한 구체적인 사용 상황이다.
Promise
그 상황에서 제품이 책임질 기대 결과를 기술한다.
Acceptance Check
기대 결과의 충족 여부를 결정적으로 판단한다. 모든 Promise는 최소 하나를 가진다.
Aspect
여러 Promise에 함께 적용되는 공통 정책이다. 초기 10편과 +10편 규칙이 한 사례다.

Traceability

코드 주석이 계약을 가리킨다

앱에는 일반 주석이지만 audit 스크립트는 이를 계약 참조로 읽는다. 태그는 연결을 증명하고 테스트는 동작을 증명한다. 

// @promise promise:graph-neighbor-papers
// @aspect aspect:paper-card-list-windowing
// @check acceptance-check:graph-neighbor-papers-paginated-window

Executable evidence

10번째는 보이고 11번째는 보이지 않는다

Vitest는 논문 12편의 fixture를 jsdom에 렌더한다. DOM에서 10번째 논문과 더보기 (10/12)를 찾고 11번째 논문은 없는지 확인한다.

Ledger

조건마다 실행 위치를 남긴다

Evidence Ledger는 자동 보고서가 아니다. 에이전트 또는 인간 전문가가 각 Promise#AcceptanceCheck를 실행 명령과 테스트에 연결한다. 행이 없으면 정책은 선언됐지만 증명 방법은 없다.

Validation limit

스크립트는 표현된 규칙만 판정한다

validator는 ID, 연결과 필수 항목을 검사한다. 여러 문서에 적힌 숫자가 모두 같은지, 정책이 인간의 의도를 충분히 표현하는지는 의미 리뷰가 맡는다.

Runner

테스트가 하나도 없으면 증거도 없다

Vitest의 -t는 이름이 일치하는 테스트만 선택한다. 필터가 낡으면 아무 동작도 검증하지 못한다. Evidence runner는 최소 한 개의 테스트가 선택되는지 먼저 확인한다.

Before and after agents

실행자는 바뀌어도 제작 원리는 남는다

AI 이전에는 인간 전문가가 인터뷰, 정책 문서, 구현, 테스트와 추적표를 나누어 관리했다. 업무 매뉴얼과 체크리스트가 작업 순서를 안내하고, 빌드와 테스트 스크립트가 반복 검사를 수행했다.

AI 에이전트는 이 작업 사이를 빠르게 이동한다. 스킬은 조직의 업무 순서와 권한 경계를 알려준다. 인간은 제품의 의미를 결정하고, 에이전트 또는 인간 전문가는 결정을 실행 가능한 구조로 변환한다. 기계가 확인한 결과는 다시 인간의 판단으로 돌아간다.
