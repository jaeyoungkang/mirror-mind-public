# Q1: 제품과 기술의 정합

- 문항: 5개
- 권장 시간: 10분
- 답변 길이: 문제마다 두 문장 이내

## 1. 구현과 outcome

검색 기능의 acceptance test는 모두 통과했지만 PDF 열기, 라이브러리 추가, 논문 선택 시간은 측정하지
않는다.

**지금 증명된 것과 아직 증명되지 않은 것을 하나씩 적어라.**

<details markdown="1">
<summary>정답·판단 기준</summary>

구현 계약 충족은 증명됐지만 연구자가 유용한 논문을 더 빠르게 찾았다는 outcome은 증명되지 않았다.
Proxy 행동과 time-to-action을 측정하고 비교 가능한 기준선을 함께 둬야 한다.

</details>

## 2. Promise와 architecture decision

다음 세 문장을 분류하라.

```text
A. 공유·새로고침·Back으로 같은 검색 조건을 다시 실행한다.
B. 검색 조건은 URL이 단독으로 소유하고 검색 전에 DB record를 만들지 않는다.
C. 코드가 단순해야 coding agent가 흐름을 이해하고 안전하게 변경하기 쉽다.
```

**A, B, C를 제품 Promise, architecture decision, engineering characteristic에 연결하라.**

<details markdown="1">
<summary>정답·판단 기준</summary>

- A: 제품 Promise — 사용자가 관찰하는 동작
- B: Architecture decision — Promise와 특성을 달성하려 선택한 구조
- C: Engineering characteristic — 코드에 기대하는 변경 용이성과 agent 이해가능성

뒤에 Promise가 생겼다는 사실로 B가 자동으로 좋은 결정이 되지는 않는다. 대안과 실제 복잡도 evidence를
비교해야 한다.

</details>

## 3. 비동기 AI 해설의 exact match

검색 결과 A로 AI 해설을 요청한 뒤 filter가 바뀌어 현재 목록은 B가 됐다. A를 읽은 AI 응답이 늦게
도착했다.

**요청 취소만으로 충분한가? 화면 반영 직전에 무엇을 비교해야 하는가?**

<details markdown="1">
<summary>정답·판단 기준</summary>

취소만으로 충분하지 않다. Commit 직전에 AI가 읽은 result-basis identity와 현재 visible
result-basis identity를 비교하고 다르면 반영하지 않는다. 취소는 효율화이고 identity 검사는
correctness guard다.

</details>

## 4. 저장과 재생성

탐색 AI 해설은 약 3,000 token, gap report는 약 10,000 token과 긴 대기 시간이 든다.

**현재 맥락에서 무엇을 저장하고 무엇을 재생성하는 것이 적합한가? 결정을 다시 열 trigger도 적어라.**

<details markdown="1">
<summary>정답·판단 기준</summary>

탐색 해설은 현재 snapshot에서 재생성하고, 비싸고 느린 gap report는 artifact로 저장·재사용한다. 반복
생성·재방문·비용·latency가 커지거나 gap 생성이 충분히 가벼워지면 각각의 결정을 다시 연다.

</details>

## 5. Gap report의 상태와 접근

Gap report는 `/gap/:id`에 저장된다. 비가입자는 접근할 수 없지만 가입자는 생성자가 아니어도 읽을 수
있고 사용자 수정·삭제 기능은 없다.

**URL, DB record, principal의 역할과 생성자 ID 일치로 읽기를 제한하는 구현의 verdict를 설명하라.**

<details markdown="1">
<summary>정답·판단 기준</summary>

URL은 artifact를 식별하고 DB record가 상태 정본이며 principal은 가입자 read authorization 입력이다.
사용자 소유권이 없는 정책과 생성자 일치 제한이 불일치하므로 `degraded`다. 생성자 ID는 필요하다면
provenance로만 사용한다.

</details>
