# Q2: 거시 구조

- 문항: 5개
- 권장 시간: 10분
- 범위: 책임 있는 경계, 최소 권한, 의존성 그래프, 배포 topology, 핵심 실행 경로

## 1. 책임 있는 경계와 pass-through layer

```ts
function wrapReviewedPapers(db, userId) {
  return { reviewedPapers: listReviewedPapers(db, userId) };
}

function loadMyLibrary(authenticatedUser) {
  return listReviewedPapers(db, authenticatedUser.id);
}
```

첫 함수는 결과를 포장할 뿐이고, 둘째 함수는 일반 사용자에게 자기 라이브러리를 읽는 기능만 제공하며
범용 조회를 숨긴다.

**어느 함수가 책임 있는 경계이고 어느 함수가 pass-through layer에 가까운가?**

<details>
<summary>정답·판단 기준</summary>

`loadMyLibrary`는 호출자가 획득하는 능력을 제한하므로 책임 있는 경계다. `wrapReviewedPapers`는
제거해도 인증·권한·필터·동작이 달라지지 않으므로 pass-through에 가깝다.

판단 질문은 “이 계층을 제거하면 중요한 규칙을 우회할 수 있거나 숨긴 복잡성이 호출자에게 새는가?”다.

</details>

## 2. 최소 권한과 우회 가능한 내부 함수

모든 API는 `loadMyLibrary(authenticatedUser)`만 사용한다는 테스트를 통과한다. 그러나 임의 `userId`를
받는 `loadLibrary(userId)`도 모든 서버 코드에서 자유롭게 import할 수 있다.

**현재 API 행동과 “다른 사용자를 지정할 수 없는 구조”를 각각 판정하라.**

<details>
<summary>정답·판단 기준</summary>

현재 API의 정상 행동은 `healthy`일 수 있지만 우회 불가능한 구조는 `degraded`다. Unrestricted helper가
공개되어 있다는 정적 evidence가 desired boundary와 어긋난다. 실제 오용이 없다는 사실은 미래 caller의
능력을 제한하지 않는다.

</details>

## 3. 의존성 그래프의 기계적 강제

허용 방향은 `API → policy boundary → repository`다. 문서에는 직접 import 금지가 있지만 CI 검사는
없다.

**현재 API의 행동 테스트만으로 부족한 이유와 필요한 기계적 evidence를 하나 적어라.**

<details>
<summary>정답·판단 기준</summary>

행동 테스트는 현재 caller만 고정하고 다음 변경의 직접 import를 막지 않는다. Forbidden dependency
edge를 error로 선언한 architecture lint를 CI에서 실행해 위반 시 실패시켜야 한다. 단, import guard는
함수 내부의 의미적 권한 오류까지 대신 검증하지 않는다.

</details>

## 4. 배포 topology와 상태 범위

서버 인스턴스가 세 개이고 provider 요청 한도는 계정 전체에 분당 100회다. 각 인스턴스가 자기
메모리에서 100회씩 허용한다. 한 인스턴스의 일시적 timeout도 모든 circuit breaker에 즉시 공유하려
한다.

**요청 한도 구현의 문제와 circuit breaker 상태를 무조건 공유하면 안 되는 이유를 적어라.**

<details>
<summary>정답·판단 기준</summary>

계정 전체 정책을 인스턴스별 counter가 소유하면 최대 300회를 허용하므로 scope가 불일치한다. 반면 한
서버의 일시적 network timeout을 fleet 전체에 전파하면 정상 경로까지 중단해 작은 실패를 전체 장애로
키울 수 있다. 정책과 failure model의 범위를 확인한 뒤 local 또는 shared 상태를 선택한다.

</details>

## 5. 핵심 실행 경로와 기계적 검증

코드는 `background-ai.ts`에 있지만 검색 route가 AI 완료를 `await`한 뒤 논문 목록을 반환한다. 제품
목표는 AI보다 논문 목록을 먼저 보여주는 것이다.

**AI는 최초 결과 표시의 핵심 실행 경로에 포함되는가? 기계적 evidence 두 가지와 사람이 결정할 항목
하나를 적어라.**

<details>
<summary>정답·판단 기준</summary>

Route가 AI를 `await`하므로 파일명과 무관하게 핵심 실행 경로에 포함된다. 정적 import·call·await graph,
runtime trace·phase timing, AI 지연·실패 주입 테스트를 조합할 수 있다. 기계는 선언과 실행의 일치를
검사하지만 “논문 목록과 AI 중 무엇을 먼저 제공할지”는 사람이 제품 Promise로 결정한다.

</details>
