# 교원 이미지 스튜디오 참여자 주도 Codex 코칭 계획안

## 핵심 전환

이 세션의 목표는 코치가 이미지 생성 문제를 대신 풀어주는 것이 아니다. 참여자가 Codex와 직접 대화하면서 자기 업무를 설명하고, 입력표를 점검하고, 이미지 생성 품질을 개선하는 방법을 익히게 하는 것이다.

코치의 역할:

- 답을 주지 않는다.
- 다음에 물어볼 좋은 질문을 제안한다.
- Codex 답변을 그대로 믿지 않게 한다.
- 결과를 검증할 기준을 참여자 입으로 말하게 한다.
- 참여자가 막히면 대신 입력하지 않고, 입력할 문장을 짧게 제안한다.

성공 장면:

> 참여자가 "이건 Codex에게 이렇게 물어보면 되겠네"라고 말하고, 직접 입력한다.

## 세션 운영 원칙

1. 참여자 키보드를 빼앗지 않는다.
2. 코치 설명은 2분을 넘기지 않는다.
3. 모든 큰 질문은 Codex에게 넘긴다.
4. Codex의 답을 다시 Codex에게 검증시킨다.
5. 이미지 생성 품질은 실제 샘플로 판단한다.

코치가 계속 붙잡을 문장:

```text
그걸 내가 답하기보다 Codex에게 어떻게 물어볼지 같이 만들어보자.
```

## 시작 멘트

```text
오늘은 제가 이미지 생성 자동화 답을 드리는 시간이 아니다.
여러분이 Codex와 직접 대화하면서 문제를 쪼개고, 필요한 기준을 만들고, 결과를 검증하는 연습을 하는 시간이다.

저는 방향을 잡아주고, 질문을 더 좋게 만드는 역할을 하겠다.
키보드는 가능한 한 여러분이 잡는다.
```

## 진행 흐름

### 1. 참여자가 Codex에게 업무 설명하기

목표: 코치가 설명하지 않고, 참여자가 자기 업무를 Codex에게 온보딩한다.

참여자에게 시킬 첫 입력:

```text
우리는 AI콘텐츠전략팀이고, 이미지 생성 서비스/이미지 스튜디오를 준비하고 있다.
현재 image prompt.xlsx에는 33개 프롬프트가 있고, BOOK1~BOOK7 그룹이 있다.
같은 BOOK 안에서는 캐릭터 생김새와 그림체가 유지되어야 한다.
공통 출력은 PNG, 416x416이다.

우리가 겪는 문제는 프롬프트를 리스트화해 대량 생성하면,
1장씩 개별 생성할 때보다 이미지 품질과 일관성이 떨어진다는 점이다.

너는 이미지 생성 품질 개선을 돕는 업무 파트너다.
먼저 우리가 이 문제를 해결하기 위해 확인해야 할 질문 5개를 해줘.
```

코치가 볼 것:

- 참여자가 자기 말로 업무를 설명했는가?
- Codex가 바로 해결책을 내놓으면, 질문부터 하라고 다시 시켰는가?
- 참여자가 Codex 질문에 직접 답하는가?

코치 개입 문장:

```text
좋다. 지금 Codex가 답을 너무 빨리 냈다. "해결책 말고 먼저 확인 질문부터 해줘"라고 다시 시켜보자.
```

### 2. Codex에게 입력표 문제 찾기 시키기

목표: 참여자가 `image prompt.xlsx`를 Codex에게 분석시켜, 입력표가 이미지 품질을 흔드는 지점을 찾는다.

참여자 입력:

```text
아래는 image prompt.xlsx의 현재 구조다.

- 컬럼: 번호, 그룹명, 프롬프트, 이미지 유형, 비율, 주의사항
- 그룹명은 BOOK1~BOOK7인데, 각 BOOK의 첫 행에만 적혀 있고 나머지 행은 비어 있다.
- 일부 프롬프트는 길고 자세하지만, 일부는 매우 짧다.
- 예: "a small raccoon looking up at the night sky"
- 예: "cooled and hardened from lava"
- 모든 행의 주의사항은 "이미지 일관성 중요"이다.

이 입력표가 대량 이미지 생성 품질과 BOOK별 일관성을 깨뜨릴 수 있는 지점을 찾아줘.
각 문제마다 왜 문제인지, 어떻게 고치면 좋을지 표로 정리해줘.
```

코치가 볼 것:

- Codex가 `BOOK` 빈칸, 짧은 프롬프트, 기준 부족, QC 기준 부재를 찾아내는가?
- 참여자가 "맞다/아니다"를 실제 업무 기준으로 판정하는가?
- 코치가 답을 추가 설명하지 않고 Codex에게 재질문하게 하는가?

재질문 예시:

```text
방금 제안 중 실제로 30개 배치 테스트 전에 꼭 고쳐야 하는 것만 우선순위 1~3으로 줄여줘.
```

### 3. Codex와 프롬프트 보강 규칙 만들기

목표: 참여자가 짧은 프롬프트를 그대로 보내면 안 된다는 것을 체감하고, 보강 규칙을 Codex와 만든다.

참여자 입력:

```text
짧은 프롬프트를 대량 생성에 그대로 넣지 않으려고 한다.
같은 BOOK 안의 일관성을 유지하려면 각 행의 프롬프트에 어떤 정보를 자동으로 보강해야 할까?

다음 항목을 포함해서 "보강 프롬프트 생성 규칙"을 만들어줘.

- BOOK 기준
- 캐릭터 기준
- 그림체/스타일 기준
- 장면 설명
- 이미지 유형
- 비율
- 텍스트/로고/워터마크 금지 조건
- 교육용 콘텐츠 안전 기준
```

이후 참여자가 직접 한 행을 골라 Codex에게 변환시킨다.

```text
아래 원본 프롬프트를 방금 만든 규칙에 따라 보강 프롬프트로 바꿔줘.

BOOK: BOOK1
원본 프롬프트: a small raccoon looking up at the night sky
공통 스타일: soft pastel storybook illustration for young children, hand-drawn look, thick rounded outlines, flat cel shading, simple clean shapes
금지 조건: no text, no letters, no numbers, no speech bubbles, no watermark, no logo
```

코치가 볼 것:

- 참여자가 원본과 보강본의 차이를 설명할 수 있는가?
- 보강본이 너무 길거나 모호하면 Codex에게 줄이게 하는가?
- 참여자가 "이 정도면 우리 업무에 맞다/안 맞다"를 판단하는가?

코치 개입 문장:

```text
내가 보기엔 이게 맞다/아니다보다, Codex에게 "이 프롬프트가 BOOK 일관성 유지에 충분한지 스스로 점검해줘"라고 시켜보자.
```

### 4. Codex에게 이미지 생성 실험 설계시키기

목표: 코치가 실험 설계를 주지 않고, 참여자가 Codex와 함께 비교 실험을 만든다.

참여자 입력:

```text
우리는 GPT 이미지 생성으로 다음 세 가지 방식을 비교하고 싶다.

1. 원본 프롬프트 그대로 개별 생성
2. 보강 프롬프트로 개별 생성
3. 보강 프롬프트를 사용해 30개 배치처럼 순차 생성

이 비교 실험을 설계해줘.
실험 대상 행, 생성 방식, 비교 기준, 성공 기준, 실패 기록 양식을 포함해줘.
```

코치가 볼 것:

- 실험이 너무 커지면 3~5개 샘플로 줄였는가?
- 참여자가 어떤 행을 먼저 고를지 직접 정하는가?
- Codex가 성공 기준을 모호하게 쓰면 다시 구체화시키는가?

재질문 예시:

```text
이 실험을 30분 안에 할 수 있게 3개 샘플만 쓰는 버전으로 줄여줘.
```

### 5. QC 기준을 Codex와 만들기

목표: 이미지가 마음에 드는지 감으로 판단하지 않고, 참여자가 Codex와 체크리스트를 만든다.

참여자 입력:

```text
생성 결과를 평가할 QC 체크리스트를 만들어줘.

1차 자동 QC와 2차 사람 QC로 나눠줘.

1차 자동 QC는 누락, 파일명, 작업 번호 매칭처럼 기계적으로 확인 가능한 항목이어야 한다.
2차 사람 QC는 캐릭터 생김새, 그림체, 장면 일치, 교육용 적합성, 텍스트/로고 혼입 여부를 판단해야 한다.

각 항목은 통과/실패로 체크할 수 있게 만들어줘.
```

코치가 볼 것:

- 참여자가 QC 항목을 자기 업무 언어로 수정하는가?
- `이미지 일관성 중요` 같은 추상 표현을 체크 가능한 기준으로 바꾸는가?
- 실패 사유가 재생성 프롬프트로 이어질 수 있는가?

재질문 예시:

```text
"그림체 유지"를 사람이 10초 안에 판단할 수 있는 더 구체적인 체크 항목으로 쪼개줘.
```

### 6. 마무리: 다음에 혼자 다시 시작하게 만들기

마무리 질문:

- 오늘 Codex에게 제일 잘 물어본 질문은 무엇인가?
- 다음에 혼자 시작한다면 첫 프롬프트를 어떻게 쓸 것인가?
- 30개 배치 테스트 전에 반드시 채워야 할 입력표 컬럼은 무엇인가?
- 이미지 생성 결과가 실패했을 때 Codex에게 어떤 식으로 재질문할 것인가?
- 우리 팀이 다음 주에 바로 해볼 30분 실험은 무엇인가?

마지막에 참여자가 직접 Codex에게 입력하게 할 문장:

```text
오늘 논의한 내용을 바탕으로, 우리가 다음 주에 혼자 실행할 수 있는 30분짜리 이미지 생성 품질 개선 실험 계획을 만들어줘.
입력 준비물, 실행 순서, 성공 기준, 실패 기록 양식을 포함해줘.
```

## 코치 행동 체크리스트

- [ ] 참여자가 직접 Codex에 입력했는가?
- [ ] 코치가 2분 이상 설명하지 않았는가?
- [ ] Codex 답변을 다시 검증시키게 했는가?
- [ ] 참여자가 자기 업무 기준으로 답변을 수정했는가?
- [ ] 이미지 생성 품질을 실제 샘플과 QC 기준으로 판단했는가?
- [ ] 다음에 혼자 쓸 첫 프롬프트를 참여자가 만들었는가?

## 하지 말 것

- 코치가 API/모델/배치 구조를 먼저 설명하지 않는다.
- 코치가 프롬프트를 대신 완성하지 않는다.
- 코치가 이미지 품질 판정을 대신하지 않는다.
- "이렇게 하면 된다"로 끝내지 않는다.
- 참여자가 Codex와 대화하지 않은 채 문서만 만들지 않는다.

## 운영 주의사항

### 1. 기대를 "한 번 좋은 이미지"에서 "반복 조건 찾기"로 옮긴다

참여자들은 Codex가 이미지 생성 품질을 바로 해결해주길 기대할 수 있다. 초반에 이렇게 잡는다.

```text
오늘은 좋은 이미지를 한 번 뽑는 것보다, 좋은 이미지가 반복해서 나오게 만드는 조건을 찾는 시간이다.
```

### 2. 코치가 너무 잘 풀어주지 않는다

참여자가 막히면 설명하지 말고 질문으로 돌린다.

```text
그걸 Codex에게 뭐라고 물어볼까?
```

코치 설명이 길어지면 세션은 코칭이 아니라 컨설팅이 된다.

### 3. 이미지 생성 실험을 작게 유지한다

30개 전체를 바로 돌리면 시간도 많이 쓰고 실패 원인도 흐려진다. 먼저 3개 샘플만 고른다.

- 짧은 프롬프트 1개
- 긴 프롬프트 1개
- 실패 예시와 가까운 프롬프트 1개

### 4. "일관성"을 체크 가능한 항목으로 쪼갠다

`이미지 일관성 중요` 같은 표현은 그대로 두면 검수 기준이 되지 않는다. 참여자가 Codex에게 아래처럼 쪼개게 한다.

- 선 굵기
- 색감
- 캐릭터 눈/얼굴형
- 주요 의상/소품
- 배경 밀도
- 그림체 복잡도
- 텍스트/로고/워터마크 혼입 여부

### 5. 모델 비교로 너무 빨리 가지 않는다

ChatGPT image, 나노바나나, 기타 모델 비교는 매력적이지만, 입력표와 QC 기준이 고정되기 전에는 비교 의미가 약하다.

먼저 같은 입력과 같은 기준을 만든 뒤 모델을 비교한다.

### 6. 참관자가 흐름을 빼앗지 않게 한다

참관자 2명이 질문하거나 답을 줄 수 있다. 질문은 받되 키보드는 코칭 대상자에게 둔다.

참관자가 답을 주기 시작하면 이렇게 되돌린다.

```text
좋은 관찰이다. 그걸 참여자가 Codex에게 질문으로 바꿔보자.
```

## 코치의 기본 문장

```text
좋다. 그 판단을 Codex에게 어떻게 물어볼까?
```

```text
Codex가 그렇게 답했는데, 이게 실제 업무 기준으로 맞는지 다시 검증시켜보자.
```

```text
내가 답을 주기보다, 지금 나온 실패 이유를 바탕으로 재요청 프롬프트를 직접 만들어보자.
```
