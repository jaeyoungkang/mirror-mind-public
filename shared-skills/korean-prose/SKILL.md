# Korean Prose Skill

Mirror Mind Public의 주요 한국어 문서를 작성하거나 다듬을 때 이 규칙을 적용한다.

적용 대상은 다음과 같다.

- `learning/**/*.md`
- `stories/**/*.md`
- 최상위 안내 문서와 새 README
- 공개 설명문과 기술 가이드

형식이 고정된 JSON, 자동 생성 HTML, 코드와 prompt 본문에는 적용하지 않는다.

## 직접 서술

제품과 시스템이 어떻게 작동하는지 구체적인 동사로 서술한다. 모호한 비유나 가상 인용으로 동작을
가리지 않는다.

### 모호한 비유를 줄인다

추상적인 비유는 처음 정의할 때만 사용한다. 이어지는 본문에서는 구체적인 어휘로 풀어 쓴다.

- 피할 표현: “도장찍기로 통과한다.”
- 권장 표현: “review verdict가 `met`이어도 근거가 비어 있으면 통과하지 못한다.”

- 피할 표현: “코드 본문의 거짓말을 잡는다.”
- 권장 표현: “vitest가 놓친 invariant 위반을 검출한다.”

비유가 꼭 필요하면 같은 문장이나 다음 문장에서 의미를 설명한다. 한 문서 안에서 같은 비유를 여러
형태로 반복하지 않는다.

### 가상 인용을 쓰지 않는다

인물의 가상 발화를 따옴표로 만들어 넣지 않는다. 사용자가 무엇을 보고 어떻게 행동하는지 직접 쓴다.

- 피할 표현: “운영자가 ‘AC 의미가 바뀌었구나’라고 판단한다.”
- 권장 표현: “운영자는 변경 표시를 보고 AC 의미가 바뀌었음을 확인한다.”

### 사용자를 익명으로 표기한다

개별 사용자, 리뷰어, 동료의 실명과 계정 이름을 산문에 적지 않는다. 출처가 필요하면 “사용자 의견”처럼
일반화하거나 issue, PR, 문서 경로처럼 중립적인 식별자를 사용한다.

### 명사구로 문장을 끝내지 않는다

영어 문장을 옮긴 듯한 명사구 종결을 줄인다. 특징을 소개한 뒤 실제 동작이나 효과를 동사로 설명한다.

- 피할 표현: “사용자에게 남아야 할 것은 통제감이라는 감각이다.”
- 피할 표현: “이 패턴의 특징은 경계의 안정성이다.”
- 권장 표현: “사용자는 실행을 시작하고 중단할 시점을 직접 결정한다.”
- 권장 표현: “이 경계는 내부 구현이 바뀌어도 호출자의 계약을 유지한다.”

### 대조형 번역투를 반복하지 않는다

“A가 아니라 B다”를 정의와 결론마다 반복하면 문장이 번역투로 굳어진다. 핵심 내용을 긍정문으로 바로
쓴다. 독자가 실제로 혼동할 두 개념을 교정할 때만 대조문을 사용한다.

- 피할 표현: “아키텍처 전문가는 정답 구조를 고르는 사람이 아니라 증거를 관리하는 사람이다.”
- 권장 표현: “아키텍처 전문가는 제품 약속을 구조와 성능 기준으로 옮기고 그 적합성을 증거로 관리한다.”

- 피할 표현: “캐시는 저장 장치가 아니라 시간에 따른 정확성 정책이다.”
- 권장 표현: “캐시 정책은 결과를 재사용할 수 있는 조건과 폐기할 시점을 정한다.”

## 문장 형태

- 한 문장에는 한 동작이나 한 사실을 담는다.
- 복문이 길어지면 두 문장으로 나눈다.
- “X하는 순간.” 같은 명사구 도입부를 쓰지 않는다.
- 콜론과 세미콜론을 줄이고 마침표로 문장을 나눈다.
- “~할 때”와 “~하는 경우”를 모두 쓸 수 있으면 “~할 때”를 우선한다.
- 같은 문서에서는 직설 문체인 “~한다”, “~이다”를 일관되게 사용한다.

## 어휘

파일 경로, 함수명, 타입명, 라이브러리 이름과 같은 영어 식별자는 본문에 직접 넣을 수 있다. 일반
개념을 설명할 때는 자연스러운 한국어를 우선한다.

- 피할 표현: “scope가 narrow하다.”
- 권장 표현: “범위가 좁다.” 또는 “scope가 좁다.”

영어 단어를 기울임꼴로 자주 강조하지 않는다. 강조가 많아지면 문장의 중심이 흐려진다.

## 구조

### 짧은 단락과 적당한 표

단락은 3~5문장 안에서 마친다. 내용이 더 길어지면 표나 bullet로 나눈다. 표 위와 아래에는 표가 보여
주는 내용을 한두 문장으로 설명한다.

같은 범주의 항목이 세 개 이상이면 bullet을 사용한다. 항목이 두 개면 산문으로 연결하는 편이
자연스럽다.

### 코드 블록과 산문을 나눈다

코드 블록 위에서 무엇을 보여 주는지 한 줄로 설명한다. 코드 블록의 내용을 바로 아래에서 같은 말로
반복하지 않는다.

### 짧은 섹션 제목을 쓴다

“왜 필요한가”, “사용법”, “사례”, “검증”처럼 짧고 직접적인 제목을 사용한다. 제목을 의문문으로 만들고
본문에서 자문자답하는 구성을 피한다.

## 작성 흐름

1. 문서 전체 초안을 쓴다.
2. 비유, 가상 인용, 명사구 종결과 대조형 번역투를 찾는다.
3. 긴 복문을 단문으로 나눈다.
4. 같은 뜻을 반복하는 단락을 합치거나 덜어 낸다.
5. commit 전에 한국어 문장과 상대 링크를 다시 확인한다.
